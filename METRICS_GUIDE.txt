ИНТЕРПРЕТАЦИЯ МЕТРИК MistRVC (v0.8.5, HiFi-GAN NSF)

Источник истины: rvc/training/train.py (+ losses.py, mel_processing.py,
visualization.py, utils/probe.py, utils/data_utils.py, configs/*.json).
Экспорт: gradio_ui/tools.py (tfevents -> txt).

1. ФОРМАТ И АГРЕГАЦИЯ

- Шаг в логах = эпоха (log_interval=1). Значение = среднее по всем батчам
  эпохи (MetricsAccumulator), усреднённое по всем GPU (all_reduce).
- Исключение: loss/g/kl - среднее, взвешенное по числу валидных кадров
  (z_mask.sum()).
- Числа в tqdm-postfix консоли = последний батч, НЕ среднее за эпоху.
  Не сравнивать их с txt.
- BucketSampler добивает корзины повторами сэмплов, поэтому число батчей
  не равно ceil(N/batch); часть сэмплов встречается дважды за эпоху.
- Экспорт: 6 знаков (LR - 10, *_frames - 0). При схлопывании файлов
  записи с шага >= начала более позднего файла отбрасываются
  (пересчёт после resume).

2. ЧТО РЕАЛЬНО ОБУЧАЕТ (backward)

Только два скаляра:

- D: loss/avg/d = сумма по 9 суб-D [ mean((1-s-D_real)^2) +
  mean((s-D_fake)^2) ], s = label smoothing.
  loss/disc_r и loss/disc_g - суммы первых/вторых слагаемых.
  Тождество: avg/d = disc_r + disc_g.
- G: loss/g/total = loss/avg/g + loss/g/fm + loss/g/mel + loss/g/kl.
  - loss/avg/g = сумма по 9 D mean((1-D_fake)^2). Только adversarial-часть,
    не весь лосс G.
  - loss/g/fm = сумма по D 2*сумма слоёв mean|feat_real - feat_fake|.
    fm_S (waveform-дискриминатор) + fm_P (8 периодных) = fm точно.
  - loss/g/mel = (сумма 8 масштабов L1 по log10-мелам) * c_mel/3 = *15
    (c_mel=45). Группы: coarse={5,10}, mid={20,40,80}, fine={160,320,480}
    мел-каналов. Тождество: coarse+mid+fine = mel.
  - loss/g/kl = KL(posterior||prior) * c_kl(=1), нормирован на кадры.
- Тождество total = avg/g + fm + mel + kl верно побатчно; в эпохальных
  средних возможно малое расхождение из-за кадрового взвешивания KL.
- 9 суб-D: S + P{2,3,5,7,11,17,23,37}. LSGAN-метки: real=1-s, fake=s,
  где s = сглаживание меток (по умолчанию 0). Равновесие (полное смешение):
  d_scores=0.5 при любом s; avg/g=2.25; disc_r=disc_g=9*(0.5-s)^2,
  т.е. при s=0: по 2.25 и avg/d=4.5.

3. ДИАГНОСТИКА (НЕ входит в backward)

- eval/d_score_g / eval/d_score_r: средний сырой выход D (не sigmoid) на
  real/fake ТРЕНИРОВОЧНЫХ батчей, среднее за эпоху. Префикс eval/ обманчив:
  это train-side метрики, одинаковые во всех режимах зонда.
  r->1, g->0 = D уверен; около 0.5/0.5 = баланс.
- grad/norm_g, grad/norm_d: L2-норма градиентов после backward, до step.
  norm_d - после клиппинга; grad/norm_d_pre_clip пишется только при
  d_grad_max_norm>0. Всплески нормальны; NaN/inf = авария.
- grad/norm_dec / enc_p / enc_q / flow / emb_g: L2 по подмодулям G;
  dec доминирует.
- learning rate/G/D: AdamW: lr = learning_rate * lr_decay^(эпоха-1)
  (config: learning_rate=1e-4, lr_decay=0.999875); D = base*d_lr_multiplier.
  betas=(0.8,0.99) и eps=1e-9 - из config; weight_decay=0.01 - дефолт
  PyTorch AdamW (в коде не передаётся явно), т.е. decoupled weight decay
  активен с коэффициентом 0.01.
- time/epoch_sec: только цикл батчей (без eval и сохранений).
- time/probe_sec: время зонда (только fixed/holdout).

4. ЗОНД (utils/probe.py)

- Режимы: off -> "Случайный", fixed -> "Обучающие данные",
  holdout -> "Исключённые данные".
- Размер по умолчанию: clamp(round(0.08*N_не-мьют), 4, 24). Берётся сплошной
  блок из середины крупнейшего исходника + по 1 соседу-margin (перекрытие
  нарезки 0.3 с). Мьюты в зонд не берутся никогда (тишина завышает метрики).
- holdout: блок+margin ИЗЫМАЮТСЯ из обучения; требует N>=40 и остаток
  >=2*batch, иначе fallback на fixed. fixed: зонд остаётся в обучении.
- Режим/размер блокируются в data/meta.json по digest filelist; смена
  filelist -> пересборка; holdout нельзя вернуть в off.
- Оценка (evaluate_probe): eval() + randomized=False -> полные 3-секундные
  сегменты (обучение видит случайные кропы 36/32/40 кадров = 0.36/0.32/0.40 с
  для 48/40/32k). RNG форкается с _PROBE_SEED=0 -> режим зонда не меняет
  траекторию обучения (при одинаковых данных и сиде fixed и off дают
  побитово идентичные loss/grad).
- eval/probe_mel_sim = clamp(100 - 100*MAE(log-мел), 0, 100). Мел
  ОДНОшкальный (128/125/80 каналов, натуральный log) - НЕ тот же мел, что в
  loss/g/mel (8 шкал, log10). Выше = лучше.
- Зонд также сохраняет PNG-спектрограммы mel/probe/real и mel/probe/fake -
  тот же одношкальный мел. Шкала - истинные dB: 0 dB = амплитуда 1.0
  (абсолютный отсчёт, не максимум картинки), пол -86.9 dB (~-87 на
  цветовой шкале): 10 ln-единиц * 20/ln(10). Цвета совпадают со старой
  ln-шкалой [-10, 0] - картинки разных версий сравнимы визуально.
  Оси (v0.8.5): вертикаль - частота в Гц, mel-шкала нелинейная (тики
  0/250/500/1k/2k/4k/8k/16k, плюс 24k при 48 kHz; mel_fmax=null -> sr/2),
  горизонталь - время в секундах, тик ~0.25 с. Разрешение по кадрам
  прежнее: 100 fps (hop 480/400/320 сэмплов для 48/40/32 kHz), 1 кадр =
  10 мс. Те же оси и шкала у mel/slice/real|fake в random-режиме.
  Тёмная верхняя область (выше ~16-20 kHz) - норма (энергии голоса там
  нет), не дефект. Сравнивать real/fake глазами на одной эпохе:
  размытие формантных полос у fake = недообученность.
- eval/probe_f0_cents / _median / _frames: см. раздел 5.

5. F0-МЕТРИКИ (visualization.py)

- F0 сгенерированного аудио оценивается автокорреляцией (кадр 40 мс,
  диапазон 50-1100 Гц, параболическая интерполяция лага, voiced-гейт:
  rms>0.003 и periodicity>0.25). Цель - pitchf из датасета (RMVPE и т.п.,
  посчитан при препроцессе). Это разные оценщики -> есть шумовой пол.
- Ошибка = 1200*|log2(f0_fake/f0_target)| центов, clamp 2400; только кадры,
  где оба voiced. 100 центов = полутон. Меньше = лучше.
- *_frames = число таких кадров. В зонде стабильно (+-1-2%); в random-режиме
  скачет из-за состава батча.
- Среднее >> медианы -> выбросы (октавные промахи, границы voiced).
  Доверять медиане; среднее - индикатор хвостов.
- Random-режим (off): теги eval/mel_sim, eval/f0_error_cents/median/frames
  считаются на ПОСЛЕДНЕМ батче эпохи (кроп, возможны мьюты). Если voiced-
  кадров нет - теги пропускаются (дырка в графике).

6. ПРАВИЛА ИНТЕРПРЕТАЦИИ

1. Здоровье: mel и все три подгруппы падают; kl падает и выходит на плато;
   fm может слегка расти (D усиливается) - это норма; градиенты без NaN;
   d_score_r около 0.55-0.6, g около 0.4-0.45, зазор растёт медленно.
2. Прогресс качества: судить по probe_mel_sim (растёт) и probe_f0_median /
   probe_f0_cents (падают), а не по тренировочному мелу.
3. Переобучение: зазор между fixed-зондом и holdout-зондом на одних и тех же
   эпохах. Малый зазор (<1-2 пункта mel_sim) = обобщает. Плато holdout при
   продолжающемся падении train-mel = убывающая отдача.
4. Коллапс D: d_score_g->0, d_score_r->1, avg/d заметно ниже равновесия
   9*2*(0.5-s)^2 (4.5 при s=0) при деградации зонда; взрывные/NaN
   градиенты.
5. Выбор чекпоинта: только по эпохам, кратным save_every_epoch;
   предпочтительно holdout; критерий - максимум probe_mel_sim при низких
   probe_f0_median и cents, стабильные frames.
6. Сравнимость: одинаковый сид + одинаковые данные -> идентичное обучение
   при любом режиме зонда. Holdout меняет данные -> траектория другая с
   1-й эпохи. Абсолютные значения зонда сравнимы только при одинаковом
   наборе сегментов, SR и данных; иначе сравнивать только тренды.

7. ТИПИЧНЫЕ ОШИБКИ (так делать нельзя)

- Считать eval/d_score_* метриками зонда - они тренировочные.
- Сравнивать loss/g/mel и probe_mel_sim численно - разные мелы и масштабы.
- Читать всплески eval/mel_sim в random-режиме как скачки качества:
  высокий sim + мало frames = тишина/мьюты в батче (тишина воспроизводится
  почти идеально и ЗАВЫШАЕТ sim). Зонд без мьютов - честный.
- Путать console-postfix (последний батч) с эпохальным средним.
- Сравнивать абсолютные probe-значения разных наборов/моделей/датасетов.
- Считать loss/avg/g полным лоссом G - это только adversarial.
- Игнорировать *_frames: малое/скачущее число кадров делает cents-метрику
  недостоверной.
- Ждать total = avg/g+fm+mel+kl до знака в эпохальных средних
  (KL взвешен по кадрам).
